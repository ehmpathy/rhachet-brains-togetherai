# 3.1.1.research.external.product.access

## summary

Together AI provides a unified OpenAI-compatible API for serverless inference of open-source models. Access requires an API key via bearer token authentication. The platform uses dynamic rate limits that adjust based on usage patterns.

---

## remote repositories

### together.ai serverless inference API

**endpoint:** `https://api.together.ai/v1/chat/completions` [1]

**authentication:** bearer token via `TOGETHER_API_KEY` environment variable [1]

**contract:** OpenAI-compatible chat completions format [1][2]

## sdk access

### official typescript SDK

**package:** `together-ai` [13]

**install:** `npm install together-ai` [13]

**usage:**
```typescript
import Together from 'together-ai';

const client = new Together({
  apiKey: process.env['TOGETHER_API_KEY'],
});

const response = await client.chat.completions.create({
  model: 'Qwen/Qwen3.5-9B',
  messages: [{ role: 'user', content: 'Hello' }],
});
```
source: [13]

**typescript version:** >= 4.9 [13]

**runtime support:** Node.js 20+, Deno 1.28+, Bun 1.0+, Cloudflare Workers, Vercel Edge [13]

## rate limits

Together AI uses **dynamic rate limits** that adjust per organization and model [14]:

> "Dynamic rate limits adjust with usage, so there are no fixed per-model limits published." [14]

**error responses:**
- `429 Too Many Requests` with `error_type: dynamic_request_limited` or `dynamic_token_limited` [14]
- `x-ratelimit-reset` header indicates seconds until retry [14]

**best practice:** send steady, consistent traffic rather than bursts [14]

> "at 60 requests per minute, distribute requests evenly (~1 per second) rather than send all 60 simultaneously" [14]

---

## tool use support

Together AI supports function/tool calls on select models [15]:

> "Pass function descriptions to the `tools` parameter, and the model returns `tool_calls` when it determines a function should be used." [15]

**best practices:**
- limit to fewer than 20 tools per call [16]
- use human-in-the-loop for sensitive actions [16]

## error handle best practices

**convergence: 3+ sources agree on exponential backoff** [17][18][19]

> "automatically retry requests with a random exponential backoff" [17]

> "Requests that time out are retried twice by default, and connection errors, 408 Request Timeout, 409 Conflict, 429 Rate Limit, and >=501 Internal errors will all be retried by default." [13]

---

## anti-patterns

**sources [16][17][18] warn against:**
- burst traffic patterns that trigger dynamic throttle
- agents with overly broad permissions
- no exponential backoff implementation
