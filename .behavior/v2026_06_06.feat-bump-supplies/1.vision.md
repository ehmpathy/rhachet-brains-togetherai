# 1.vision

## the outcome world

### day-in-the-life with this in place

a developer who builds an agentic assistant opens their config:

```ts
import { genBrainAtom } from 'rhachet-brains-togetherai';

// for quick iterations on small tasks - pennies per million tokens
const fastBrain = genBrainAtom({ slug: 'together/lfm2/24b' }); // $0.03/$0.12

// for serious code work - frontier swe-bench scores
const codeBrain = genBrainAtom({ slug: 'together/deepseek/v4-pro' }); // 80.6% swe-bench

// for multimodal tasks - vision + code
const visionBrain = genBrainAtom({ slug: 'together/gemma4/31b' }); // vision capable
```

they switch between models based on task complexity, confident each config maps to a real, production-ready model with accurate prices and specs.

### before/after contrast

| before | after |
|--------|-------|
| 10 models, some outdated | 18+ models that cover full spectrum |
| deepseek v3.1 as "frontier" | deepseek v4 pro at 80.6% swe-bench |
| no ultra-cheap options | lfm2 24b at $0.03/1M input |
| glm-4.7 at 73.8% swe | glm-5.1 at 58.4% swe-bench pro |
| kimi k2.5 at 76.8% swe | kimi k2.6 at 80.2% swe-bench verified |
| no vision models | gemma 4 31b, qwen3.5 397b with vision |

### the "aha" moment

when a developer discovers MiniMax M2.5 scores 80.2% on swe-bench verified at just $0.30/$1.20 - that's frontier-tier code performance at budget prices. same quality as kimi k2.6, 7x cheaper.

or when they realize lfm2-24b at $0.03 input lets them run 17x more inference than qwen3-coder-next ($0.50) for the same budget - rapid iteration loops that were previously cost-prohibitive.

or when they see deepseek v4 pro matched against claude opus 4.7 on swe-bench (80.6% vs 80.8%) at a fraction of the cost with cached tokens at $0.20/1M.

## user experience

### usecases & goals

| usecase | goal | model choice |
|---------|------|--------------|
| high-volume triage | classify 100K issues cheaply | lfm2/24b, gpt-oss/20b |
| serious code generation | match proprietary quality | deepseek/v4-pro, kimi/k2.6 |
| best value for code | frontier quality, budget price | minimax/m2.5 (80.2% swe @ $0.30) |
| multimodal code review | parse screenshots + code | gemma4/31b, qwen3.5/397b |
| balanced cost/quality | good results, reasonable cost | qwen3.5/9b, glm/5.1, minimax/m2.7 |
| maximum context | 500K+ token documents | deepseek/v4-pro (512K) |

### contract inputs & outputs

```ts
// input: slug selection
const brain = genBrainAtom({
  slug: 'together/deepseek/v4-pro'
});

// output: configured brain with accurate spec
brain.spec.gain.grades.swe // 80.6
brain.spec.cost.cash.input // $0.0000021 per token
brain.spec.gain.size.context.tokens // 512_000
```

### timeline: model selection

1. developer reviews `TogetherBrainAtomSlug` type for available options
2. filters by domain (SOFTWARE vs ALL) and budget
3. checks swe-bench scores for code tasks
4. selects slug, gets fully configured brain
5. swaps models as needs evolve - zero config changes beyond slug

## mental model

- **like a car rental catalog**: economy (lfm2), standard (qwen3.5-9b), premium (deepseek-v4-pro), luxury (kimi-k2.6)

## evaluation

### how well does it solve the goals?

| goal | grade | notes |
|------|-------|-------|
| fast & cheap models | excellent | lfm2 at $0.03 is 17x cheaper than current cheapest |
| big & best models | excellent | deepseek v4 pro at 80.6% rivals claude opus |
| all origins | good | qwen, deepseek, glm, kimi, llama, gemma covered |
| accurate specs | good | sourced from together.ai prices + benchmarks |

### pros

- **complete spectrum**: from $0.03/1M to $4.40/1M output
- **frontier performance**: 80.6% swe-bench verified (deepseek v4 pro)
- **multimodal options**: gemma 4, qwen 3.5 support vision
- **cache discounts**: deepseek v4 pro offers 90% discount on cached tokens

### cons

- **benchmark fragmentation**: some use swe-bench verified, others use swe-bench pro
- **price volatility**: rates change; need maintenance strategy
- **tool use support**: not all models support function calls equally

### edgecases & pit of success

| edgecase | how we handle it |
|----------|------------------|
| user picks outdated slug | typescript error - slug not in union |
| model removed from together | version bump removes slug, compile error |
| price changes | update config, bump version, changelog |

## what is awkward?

### what feels off or forced

- **benchmark score variance**: glm-5.1 scores 58.4% on swe-bench *pro* but we track swe-bench *verified* - not apples to apples
- **model names**: qwen3.5-397B-A17B is unwieldy; slug simplification helps but loses precision
- **version proliferation**: deepseek v3.1 vs v4 vs v4-pro creates migration complexity

### where design fights mental model

- users expect "latest = best" but kimi k2.5 -> k2.6 isn't just a version bump, it's a major capability jump
- "cheap" and "fast" usually correlate, but lfm2 is cheap while llama4-maverick is fast with larger context

### uncomfortable tradeoffs

| tradeoff | tension |
|----------|---------|
| completeness vs maintenance | more models = more to update |
| slug simplicity vs precision | `deepseek/v4-pro` hides variant details |
| current prices vs stability | hard-coded prices that may change |
