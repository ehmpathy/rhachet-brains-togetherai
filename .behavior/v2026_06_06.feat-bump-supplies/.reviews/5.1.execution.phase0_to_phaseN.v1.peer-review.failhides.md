# nitpick.1: Use HelpfulError.wrap instead of manual try/catch for error wrapping

**rule**: .agent/repo=ehmpathy/role=mechanic/briefs/practices/code.prod/pitofsuccess.errors/rule.prefer.helpful-error-wrap.md

**locations**:
- src/domain.operations/atom/genBrainAtom.ts

The code uses a manual try/catch block around the OpenAI client call to wrap errors into UnexpectedCodePathError for observability. While the rule acknowledges that try/catch can sometimes be useful to make errors more observable, it explicitly states that in these cases it is best to use HelpfulError.wrap (or a specific subclass like UnexpectedCodePathError.wrap) instead.

The current implementation matches the manual pattern shown in the rule as less preferred (including the if (!(error instanceof Error)) throw error; check). This should be refactored to use the .wrap() helper for consistency with the recommended pit-of-success error handling pattern.

**snippet**:
```ts
      try {
        response = await openai.chat.completions.create({
          model: config.model,
          messages,
          ...(hasTools ? { tools, tool_choice: 'auto' as const } : {}),
          ...(wantStructuredOutput
            ? {
                response_format: {
                  type: 'json_schema',
                  json_schema: {
                    name: 'response',
                    strict: true,
                    schema: jsonSchema,
                  },
                },
              }
            : {}),
        });
      } catch (error) {
        // wrap api errors with context
        if (!(error instanceof Error)) throw error;
        throw new UnexpectedCodePathError(
          `together.ai api call failed: ${error.message}`,
          {
            model: config.model,
            slug: input.slug,
            hasTools,
            wantStructuredOutput,
            cause: error,
          },
        );
      }
```
