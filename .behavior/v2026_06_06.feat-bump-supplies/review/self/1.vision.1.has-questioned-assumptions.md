# self-review: has-questioned-assumptions

## hidden assumptions surfaced

### 1. "together.ai prices from web are current and accurate"

**what do we assume?** that the prices fetched from together.ai/pricing are accurate as of june 2026.

**what evidence supports this?** live web fetch on 2026-06-06. prices documented with source links.

**what if the opposite were true?** if prices changed since fetch, users would have incorrect cost expectations. mitigated by: version bumps on updates, prices hard-coded with source comments.

**did wisher say this?** no — inferred as baseline requirement for any price catalog.

**verdict: assumption acknowledged** — prices are snapshot-in-time by design. changelog + versions handle drift.

---

### 2. "swe-bench scores from third-party sources are reliable"

**what do we assume?** benchmark scores from web search results match actual model capability.

**what evidence?** multiple independent sources report similar scores. deepseek v4 pro at 80.6% cited by codersera, benchlm, framia.

**what if the opposite were true?** models may perform differently than claimed. mitigated by: scores are guidelines, not guarantees.

**exceptions?** swe-bench "verified" vs "pro" are different benchmarks. glm-5.1 scores 58.4% on *pro*, not *verified*.

**verdict: assumption holds with caveat** — benchmark type must be clearly labeled.

---

### 3. "all new models support chat completions api"

**what do we assume?** every model listed can be invoked via openai-compatible chat completions endpoint.

**what evidence?** together.ai serverless docs suggest standard api for listed models.

**what if the opposite were true?** some models may require different endpoints or formats. would break `genBrainAtom` contract.

**did wisher say this?** no — inferred from architecture of current adapter.

**verdict: must verify** — flagged in external research needed. cannot ship without api verification.

---

### 4. "all models support tool use (function calls)"

**what do we assume?** every model can handle the `tools` parameter and respond with tool calls.

**what evidence?** current config sets `skills: { tooluse: true }` for all models. web research mentions "function call enabled" for some but not all.

**what if the opposite were true?** models without tool support would fail on agentic workloads.

**exceptions?** cheap models (lfm2, gpt-oss) may not support tools. need to verify.

**verdict: must verify per model** — cannot assume universal support. may need `skills: { tooluse: false }` for some.

---

### 5. "vision capability is additive, not disruptive"

**what do we assume?** the addition of gemma 4 31b and qwen 3.5 397b with vision support doesn't change text-only behavior.

**what evidence?** multimodal models typically handle text-only inputs normally.

**what if the opposite were true?** vision models might behave differently on pure-text prompts. unlikely but unverified.

**did wisher say this?** no — vision not mentioned in wish. inferred from "all origins".

**verdict: assumption holds** — vision is opt-in via input format. text-only works normally.

---

### 6. "users want slug simplicity over model ID precision"

**what do we assume?** `together/deepseek/v4-pro` is better than `deepseek-ai/DeepSeek-V4-Pro`.

**what evidence?** current config uses simplified slugs. brain config pattern brief recommends slug hierarchy.

**what if the opposite were true?** users who need exact model control may find slugs too abstract.

**exceptions?** quantization variants (fp8, fp4) might matter. current config doesn't expose this.

**verdict: assumption holds** — slug simplicity is the design goal. advanced users can fork config.

---

### 7. "cheap models are useful despite lower capability"

**what do we assume?** users have usecases for $0.03/1M token models despite worse benchmark scores.

**what evidence?** high-volume triage, classification, simple extraction don't need frontier capability.

**what if the opposite were true?** if no usecase for cheap models, the addition of them is noise.

**did wisher say this?** yes — "fast & cheap models" explicitly requested.

**verdict: holds** — wisher validated.
