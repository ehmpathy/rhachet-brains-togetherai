# review.self: has-play-test-convention

## the review

i checked the test file conventions in this repo.

## repo test convention

current files:
- `castContentToOutputSchema.test.ts` - unit test
- `index.unit.test.ts` - explicit unit test
- `genBrainAtom.integration.test.ts` - integration test

no `.play.test.ts` files exist in this repo.

## why journey tests are not applicable here

**what is this change?**
- add 10 model configurations to CONFIG_BY_ATOM_SLUG
- update type union TogetherBrainAtomSlug
- update getBrainAtomsByTogetherAI to include new slugs

**what is the user journey?**
1. developer imports `genBrainAtom`
2. developer calls `genBrainAtom({ slug: 'together/deepseek/v4-pro' })`
3. developer calls `atom.ask({ ... })` with prompt
4. developer receives response with output and metrics

**why integration tests cover this:**
- `genBrainAtom.integration.test.ts` already walks this exact flow
- `[case4]` tests briefs for all models - new ones now in array
- `[case9]` tests tool use for all models - new ones now in array
- `[case10]` tests full tool workflow for frontier models - new ones added

**why a separate `.play.test.ts` is not needed:**
- no multi-step user session to capture
- no state transitions between steps
- each operation is atomic (get atom, call ask)
- integration tests already use given/when/then structure

## conclusion

journey test convention does not apply to this change.

the user experience (select model → use model) is already covered by extant integration tests with BDD structure.

no `.play.test.ts` files needed.
