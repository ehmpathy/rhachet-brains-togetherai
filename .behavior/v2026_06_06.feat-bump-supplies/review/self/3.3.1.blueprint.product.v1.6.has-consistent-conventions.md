## extant conventions audit

### audit 1: slug structure

i read every extant slug:

```ts
'together/qwen3/coder-next'      // 3 parts: provider/family/variant
'together/llama3.3/70b'          // 3 parts: provider/family/size
'together/deepseek/r1'           // 3 parts: provider/family/variant
'together/deepseek/v3.1'         // 3 parts: provider/family/version
'together/deepseek/v3.1-turbo'   // 3 parts: provider/family/version-variant
'together/glm/4.7'               // 3 parts: provider/family/version
'together/kimi/k2'               // 3 parts: provider/family/version
'together/kimi/k2.5'             // 3 parts: provider/family/version
'together/meta/llama4-maverick'  // 3 parts: provider/family/variant
'together/qwen3/235b'            // 3 parts: provider/family/size
```

**convention derived:**
- always 3 parts separated by `/`
- part 1: always `together`
- part 2: model family (lowercase or mixed case)
- part 3: identifier (size, version, or variant)

### audit 2: description structure

i read every extant description:

```ts
'Qwen3-Coder-Next - optimized for agentic code (262K)'
'Llama-3.3-70B - largest llama model (128K)'
'DeepSeek-R1 - reason model (128K)'
'DeepSeek-V3.1 - frontier chat model (128K)'
'GLM-4.7 - frontier model from zhipu (200K)'
```

**convention derived:**
- pattern: `{ModelName} - {short capability} ({context}K)`
- model name matches official name
- capability is 2-4 words
- context size in parentheses with K suffix

### audit 3: spec structure

i read every extant spec:

```ts
spec: {
  cost: { cash: { input: 0.0000005, output: 0.0000012 } },
  gain: {
    size: { context: { tokens: 262_000 } },
    grades: { swe: 74.2 },
  },
},
```

**convention derived:**
- cost.cash.input: per-token rate (decimal)
- cost.cash.output: per-token rate (decimal)
- gain.size.context.tokens: number with underscores
- gain.grades.swe: benchmark score or null
