# review.self: has-ergonomics-reviewed

## input/output ergonomics review

### genBrainAtom({ slug })

**input review:**
- input: `{ slug: 'together/deepseek/v4-pro' }`
- natural? yes. single string slug follows convention from other brain packages.
- friction? none. no config, no api keys, no options at instantiation.

**output review:**
- output: `BrainAtom` with `.ask()`, `.slug`, `.spec`
- natural? yes. standard brain interface, familiar to users of rhachet brains.
- friction? none. spec contains cost/gain, ready to inspect or use.

**pit of success check:**

| principle | status | articulation |
|-----------|--------|--------------|
| intuitive design | ✓ | slug follows `provider/family/model` pattern. self-descriptive. |
| convenient | ✓ | no setup required. import, call, use. |
| expressive | ✓ | slug hierarchy allows filter by family (e.g., all `together/deepseek/*`). |
| composable | ✓ | BrainAtom conforms to rhachet brain interface. works with repl, orchestrators. |
| lower trust contracts | ✓ | type union validates at compile time. runtime throws on invalid config. |
| deeper behavior | ✓ | spec.cost.cash includes input/output rates. spec.gain includes context size, swe-bench scores. |

## non-issues articulated

1. **slug convention is natural**
   - why it holds: follows `provider/family/model` pattern used across rhachet brain packages
   - users familiar with `xai/grok/4` will expect `together/deepseek/v4-pro`

2. **spec structure is natural**
   - why it holds: `spec.cost.cash.input` and `spec.gain.grades.swe` are self-descriptive
   - matches domain language: cost in dollars, gain in capability scores

3. **no configuration at instantiation**
   - why it holds: api key is provided at `.ask()` time via context, not at instantiation
   - enables catalog exploration without credentials
