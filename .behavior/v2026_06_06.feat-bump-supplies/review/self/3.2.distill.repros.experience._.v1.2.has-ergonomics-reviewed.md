## questions asked and answered

### question 1: is the slug format intuitive?

**the format:** `together/deepseek/v4-pro`

**why it holds:**
- `together` = provider name, matches the package name `rhachet-brains-togetherai`
- `deepseek` = model family, matches how users think about models
- `v4-pro` = specific variant, matches how together.ai names them

**could it be simpler?**
- could omit `together/` prefix since package already implies provider
- but: consistency with other brain packages (`xai/grok/4`) is worth the extra characters
- explicit provider prefix enables future multi-provider packages

**verdict:** holds. the redundancy is acceptable for consistency.

### question 2: why no configuration at instantiation?

**the design:** `genBrainAtom({ slug })` - no api key, no options

**why it holds:**
- api key is a runtime concern, not a catalog concern
- user can explore catalog without credentials
- key is injected at `.ask()` via context, where it belongs

**could it be different?**
- could require api key upfront like openai sdk
- but: that blocks exploration and test
- current design: import → explore → commit

**verdict:** holds. deferred configuration is correct.

### question 3: is spec.cost.cash structure natural?

**the structure:** `spec.cost.cash.input`, `spec.cost.cash.output`

**why it holds:**
- mirrors how together.ai prices: per-1M-token input/output rates
- consistent with other brain packages
- enables cost calculation: `tokens * spec.cost.cash.input`

**could it be different?**
- could use `pricePerToken` as single number
- but: input/output rates differ, sometimes dramatically (10x)
- current design makes cost estimates accurate

**verdict:** holds. split rates match provider model.

### question 4: what happens with an invalid slug?

**path 1: compile-time** - typescript rejects unknown strings
- `genBrainAtom({ slug: 'typo/wrong' })` → compile error
- this is the intended path for most errors

**path 2: runtime bypass** - if types are bypassed via `as any`
- `CONFIG_BY_ATOM_SLUG[slug]` returns undefined
- attempt to access properties throws
- error message will be unclear

**potential improvement:**
- could add runtime guard: `if (!config) throw BadRequestError`
- would give clearer error for runtime misuse

**verdict:** acceptable. type system handles 99% of cases. runtime guard could be added but is not urgent for this change.

### question 5: why array return for getBrainAtomsByTogetherAI?

**the design:** returns `BrainAtom[]`, not a map or index

**why it holds:**
- 20 models is small enough for linear search
- array enables: `.filter(a => a.spec.cost.cash.input < 0.0000005)`
- map by slug would duplicate what `genBrainAtom` already does

**could it be different?**
- could return `Record<slug, BrainAtom>` for O(1) lookup
- but: defeats purpose of discovery (already know slug)
- array is for filter/sort/explore

**verdict:** holds. array is correct for catalog discovery.

## conclusion

reviewed each input/output decision. found no friction that needs a fix.

one potential improvement noted (runtime guard for invalid slugs) but not a blocker for this change.
