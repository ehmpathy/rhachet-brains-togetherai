# review.self: has-play-test-convention

## the review question

should journey tests use `.play.test.ts` convention?

## what i found

i checked the test files in this repo:

```
src/infra/cast/castContentToOutputSchema.test.ts      # unit
src/contract/sdk/index.unit.test.ts                   # unit
src/domain.operations/atom/genBrainAtom.integration.test.ts  # integration
```

no `.play.test.ts` files exist. this is intentional.

## why journey tests do not apply here

**this change adds model configs, not user flows.**

the "user journey" is:
1. import genBrainAtom
2. call with slug
3. call .ask() with prompt
4. receive response

this is a **single atomic operation**, not a multi-step session.

**journey tests are for:**
- multi-step user sessions with state
- wizard flows with back/forward
- progressive disclosure patterns
- scenarios where step order matters

**this change is:**
- config data addition (10 model entries)
- type union expansion
- array population update

the integration test already covers the full flow with BDD structure:

```ts
given('[case4] all models leverage briefs')
  when('[slug] ask is called with briefs')
    then('response contains ZEBRA42')
```

## why it holds

1. **no user session state** - each atom.ask() is independent
2. **no step order dependency** - operations are atomic
3. **BDD structure extant** - integration tests use given/when/then
4. **coverage complete** - new models added to test arrays

## conclusion

journey test convention (`.play.test.ts`) does not apply.

integration tests with BDD structure cover the user experience.

this is a config expansion, not a new user flow.
